## 一、系统角色与端到端流程

### 1.1 四个节点

| 角色 | 代码位置 | 硬件 | 在系统中的职责 |
|---|---|---|---|
| **Gateway** 网关 | `uwb_gateway/Src/gateway_cmd.c` (3347 行) | STM32L412 + DW3210 | PC 与 UWB 空口之间的桥：接 PC 的 AT 命令、翻译成 UWB 帧发给基站；收标签/基站的 UWB 帧，转成 ASCII 行回给 PC。**不参与定位、不占槽**（`example_selection.h`："pure sniffer, no anchor role"） |
| **Anchor** 基站 | `shared/fusion_anchor/fusion_anchor.c` (3300 行) | STM32L412 + DW3210 | 角色二合一（M3 起：**区参考锚点**（`cs_level=0`，占本区槽 0，定义区栅格原点、广播区时隙表、跑本区 DS-TWR 修正、填 presence 位图）与 **区成员**（`cs_level=1`，按网关下发的区时隙表排自己的槽）。**没有选举、没有父子树、没有 ALOHA**）。广播 75 字节 TimeSync 信标 |
| **Tag** 标签 | `shared/fusion_tag/fusion_tag.c` (2431 行) | STM32L412 + DW3210（机器人携带） | 被动收信标、算 TDOA、**按区聚类后逐区解算**（M4：跨区不配对、无有效区不出位置）、**自己解算后**把结果广播给网关；同时通过本地 UART 输出 ASCII 行给机器人 |
| **Host** 上位机 | `uwb_gateway_py/uwb_host.py` (4819 行) | PC / Python-Tkinter | 组网编排、坐标配置、地图渲染、OTA 进度、离群剔除与轨迹平滑 |

关键设计：**网关不解算位置**，标签解算完再上报结果（`FUNC_DL_POS_REPORT 0xE3`）。网关只做转发与统计。

### 1.2 六段主流程

```
[上电]  Anchor 初始化 → 广播 0xEC DISCOVERY → 等网关下发 NETWORK_START
   │      (M3：不再扫频选举层级，只等网关指定"我在哪个区、谁是参考、我在第几槽")
[发现]  Anchor 周期广播 0xEC DISCOVERY ──► Gateway 登记设备 ──► Host 设备列表
   │            Gateway 发 0xF3 FIND_ACK，Host 触发 AT+FIND
[配坐标] Host: AT+COORD=uid,x,y,z ──UWB 0xF4──► Anchor 存坐标 + 置 COORD_VALID
   │      (flash 持久化当前是 stub，未生效)
[组网]  Host: AT+NETSTART=root_rank,r1,r2,... ──► Gateway 连续 2s、每 20ms
   │      广播 0xE8 NETWORK_START（携带名册 + 区时隙表 + 区参考锚点）
   │      ──► Anchor 回 0xE9 ACK（单播给网关），不在名册里的直接静默
   │      ⇒ Anchor 由 NET_IDLE → NET_RUNNING（无 NET_STARTING / ALOHA 试探）
[跑栅格] 本区参考锚点占槽 0，8 槽 × 6.25 ms = 50 ms/轮，20 Hz 信标；
   │      成员按网关下发的区时隙表入槽，未入槽者发 slot=255（标签排除）
   │      参考锚点每轮批量广播 0xE7 TWR_CORR（各成员路径修正）
[解算]  Tag 每轮解一次（20 Hz）：
   │      收信标 → 维护各锚 tracker → 按区聚类 → 逐区槽补偿 TDOA 装配
   │      → Gauss-Newton → 质量分 → 选一个区的结果发布（M4）
   │      (无有效区 ⇒ 不出位置，quality=65535，绝不输出质心)
[上报]  Tag 在槽 0 保护窗发 26B 位置帧 0xE3 ──► Gateway ──ASCII "+POS,..."──► Host 渲染
```

旁路流程：**降级/保活**（所有区的参考锚静默 2 s → 2 Hz 降级帧；全网静默 → 1 s 本地保活帧）、**OTA**（`gw_ota.c` SW-ARQ + `AT+OTA_BCAST`）。

### 1.3 帧与功能码

| 功能码 | 名称 | 方向 | 长度 | 用途 |
|---|---|---|---|---|
| `0xE1` / `0xE2` | COORD_READ / COORD_REPORT | GW↔Anchor | 13 | 坐标回读 |
| `0xE3` | DL_POS_REPORT | Tag→广播 | 26 | 位置上报（含 zone_id） |
| `0xE4` | OTA_END | GW→Dev | — | OTA 完成重启 |
| `0xE5` / `0xE6` | OTA_PREPARE / ACK / ABORT | GW↔Dev | — | OTA 换频准备 |
| `0xE7` | TWR_CORR | Root→广播 | 12+4n | DS-TWR 路径修正批量 |
| `0xE8` / `0xE9` | NETWORK_START / ACK | GW→广播 / Anchor→GW | 55 / 20 | 组网（含 zone_id / 时隙表 / 时基 / 区参考锚点） |
| `0xEA` / `0xEB` | ZONE_SYNC_REQ / ZONE_SYNC_RSP | Anchor↔Anchor | 25 | 区域内时钟同步（**协议已定义，M3 未实现**） |
| `0xEC` | ANCHOR_DISCOVERY | Anchor→广播 | 24 | 设备发现 |
| `0xED` | CLOCK_FEEDBACK | 观察者→单播 | 27 | 同步误差反馈 |
| `0xEE` | DOWNLINK_BEACON (TimeSync) | Anchor→广播 | 75 | 时钟信标 / 时隙表 / 坐标 / 区信息 |
| `0xF0`..`0xFE` | 网关配置协议 | GW↔Dev | — | PREP/FIND/COORD/OTA/START/STOP/LIST |

#### 区网格字段（2026-11-24，M2）

协议先"加字段"再"改语义"，这样新旧固件可以在同一片场里共存：

| 帧 | 新增字段 | 字节 | 含义 |
|---|---|---|---|
| `0xE8` NETWORK_START | `zone_id` | [14] | 本次组网所属区；`0xFF` = 未分区 |
| | `n_slots` | [15] | 区时隙表有效项数 |
| | 区时隙表 | [32..47] | 8×u16，项 i = 名单第 i 个成员的 TDMA 槽；`0xFFFF` = 无 |
| | `zone_time_base` | [48..52] | 区的公共时间原点（40 bit DTU） |
| `0xE9` NETWORK_ACK | `zone_id` | [15] | 我加入的区 |
| | `ref_rank` | [16..17] | 我选的时钟参考锚点；`0xFFFF` = 还没选 |
| `0xEE` DOWNLINK_BEACON | `zone_id` / `link_quality` / `zone_role` | [65][66][67] | 我属于哪个区、链路质量、区内角色 |
| | `zone_ref_ts` | [68..72] | 参考锚点的时钟（40 bit DTU） |
| `0xE3` DL_POS_REPORT | `zone_id` | [22] | 本次解算所在的区；`0xFF` = 未分区 |

- **区字段为什么放在帧尾而不是复用 `cs_level` 字节**：`cs_level` 目前同时被基站的选举逻辑和标签的 Root 识别逻辑读写，在 M3 之前改它的语义会让这两处读到垃圾。字段加在帧尾，语义改动推迟到 M3。
- **`zone_time_base` 有一个有效标志**（NETWORK_START 的 flags bit1）。网关自己的时钟与各基站不在同一时基上（每颗 DW3000 上电从 0 起算），在有成员公布参考之前网关**编不出**一个有意义的时基，所以该位保持清零，基站就不会把一个 0 当成真的时间轴。
- **时隙表由网关统一下发**：旧设计里每个基站靠自己听到的邻居各猜一张表（`tdma_build_table_from_neighbors()`），两张表对同一栅格给出不同的"轮到谁"，迟到的信标因此落到错误的槽里，而标签会把这段时差当成真实的 TDOA。现在整个区只有一张表。
- **名单区偏移不变**：NETWORK_START 的名单仍在 [16]（旧固件按同样偏移读），所以新网关的 53 字节帧能被旧固件正确读出名单。

#### 区网格字段（2026-11-24，M3：去 Root 化）

M3 把"基站组成一棵树、有一个 Root"改成"基站组成若干区，每区有一个**参考锚点**"。

| 帧 | 字段 | 字节 | 含义 |
|---|---|---|---|
| `0xE8` NETWORK_START | `zone_ref_rank` | [53..54] | **本区的时钟参考锚点**（u16 LE）。由网关从上位机给的 `AT+NETSTART=<root_rank>` 取来，**上位机主导** |
| | 帧长 | 53 → **55** | `FUNC_NETWORK_START_LEN 55` |
| `0xEE` DOWNLINK_BEACON | `cs_level` 字节语义 | [15] | **0 = 本区参考锚点，1 = 普通成员**（旧语义是选举树的层号） |
| | `slot` 字节语义 | [18] | **255 = 尚未取得 DS-TWR 修正、未入槽**；否则是自己的槽号 |
| | `zone_role` | [67] | `0 = 成员`，`1 = 参考锚点` |

M3 在基站内**删除**的东西：

- **选举**：无 `STATE_SCAN` / `STATE_ELECTING` / `STATE_ORPHAN` 三态，无 `parent_eui64` / `parent_rank` / `last_parent_rx_ms`。锚站不再"找爹"，只等网关下发"你在哪个区、谁是参考、你在第几槽"。
- **ALOHA 兜底**：无 `s_aloha_mode` / `s_aloha_sent_ms`、无 `NET_STARTING` / `NET_WAIT_CONFIRM`、无 `NET_ALOHA_RETRY_MS` 重发。未入槽的成员**按栅格发**但把 `slot` 字节写成 255，标签据此把它排除——不再需要抢信道。
- **Root 独占的时隙表构建**：`tdma_build_table_from_roster()` / `tdma_build_table_from_neighbors()` / `parse_slot_table()` / `is_in_root_slot_table()` 全部删除，改为**全网一张表**：网关下发区时隙表，成员各自 `tdma_build_table()` 反查成 `slot_owners[slot] = rank`，并取自己名册下标对应的槽。参考锚在信标里**公布**这张表，成员收到时**只做一致性检查**（不一致打一条一次性告警），**不再采纳**——表只有一个来源，就是网关。
- **参考锚点钉在槽 0**：区的时钟参考锚点**永远占槽 0**，其余成员按名册顺序占槽 1、2、3…（网关写时隙表时显式这么排，不依赖"参考锚恰好在名册第一位"）。理由：标签的上行保护窗是"参考锚信标之后的那段空档"，而标签识别参考锚靠的是 `(slot == 0 && level == 0)`——参考锚要是占了别的槽，标签就既没有栅格原点也没有上报窗口。
- **参考锚点必须在名册里**：网关把参考锚点强制插到名册第 0 位；名册已满（8 个）又没包含参考锚点时**拒绝组网**（`+NETSTART_ERR,ROOTNOTINROSTER`），而不是悄悄踢掉一个操作员选中的基站。参考锚不在区里 ⇒ 整区没有时间轴。
- **Root 的时钟路径**：全局唯一栅格原点、Root 独占的 TX 时刻环形表、`root_clock_to_local()` 全部改成"区参考锚"版本（`s_zone_grid_base` / `ZONE_REF_TX_HIST` / `zone_ref_clock_to_local()`）。区里的每个成员都直接跟参考锚做 DS-TWR 往返，**没有中间层**。

M3 **新增**的东西：

- `am_zone_ref()`：判断"我就是本区参考锚点"。参考锚负责闭合本区成员的 DS-TWR 往返、填 presence 位图、**没有**父子表、**不**管别的区。
- 参考锚点的选择**由网关指定**（上位机给 `AT+NETSTART=<root_rank>`），不是锚站开机抢的。这既符合"上位机主导组网"，也消掉了"开机时互相听不见 ⇒ 选举永远出不来"的死锁。
- `zone_ref_ts`（40 bit DTU）：成员收到参考锚的信标时记下参考锚的时钟，作为该区公共时间轴上的一个刻度。
- `DL_REF_STALE_MS 3000`：成员超过 3 s 没收到参考锚的信标 ⇒ `tdma_may_tx()` 拒绝发（宁可不发，也不能在错的时基上发）。

网关侧另有 `gateway_protocol.h` 定义的 `FUNC_PREP_CMD 0xF0`、`FUNC_FIND_REQ 0xF2`、`FUNC_COORD_WRITE 0xF4`、`FUNC_OTA_DATA 0xF6`、`FUNC_START_TDOA 0xF8`、`FUNC_NETWORK_CFG 0xF9`、`FUNC_STOP_TDOA 0xFA`、`FUNC_LIST_REQ 0xFD`。

#### 区网格字段（2026-11-24，M4：标签侧生效）

M2 把"区"这套字段铺到协议和线路上，M3 让**基站侧**的区字段生效，M4 让**标签侧**的区字段真正生效。

| 帧 | 字段 | 字节 | 含义 |
|---|---|---|---|
| `0xEE` DOWNLINK_BEACON | `zone_id` | [65] | 发送者所属的区（`DL_ZONE_ID_NONE 0xFF` = 不属于任何区） |
| `0xE3` DL_POS_REPORT | `zone_id` | [22] | **这个位置是在哪个区解出来的**。同一组 (x,y) 在不同区含义不同，所以区是位置的一部分 |

标签侧按区维护的东西（`TagZoneBucket s_zones[DL_MAX_ZONES 4]`）：

| 桶内字段 | 含义 |
|---|---|
| `ref_rank` / `ref_rx_ms` / `ref_seen` | 本区参考锚的 rank、上次听到的时刻 |
| `ref_toa_eq` / `ref_cycle` / `ref_toa_valid` | 本区参考锚的槽补偿 TOA 及其轮次（TDOA 配对的基准） |
| `rate` / `rate_buf[]` / `rate_n` | 本区的时钟比（标签钟 / 参考锚钟），最近 5 次的中位数 |
| `last_rx_ms` / `seen` | 本区任意锚点的上次心跳 |

标签侧按区改掉的逻辑：

- **无区不是桶**：`zone_id == 0xFF` 的锚点被跟踪但不参与任何解算。
- **跨区不配对**：一个锚的 `tdoa_avg` 只与**本区**参考锚的 TOA 配对；锚换区时它的 `tdoa_avg` 被**清零**（旧区参考锚配出来的值在新区没有意义）。
- **逐区解算**：见 §3.4。
- **无有效区不出结果**：见 §3.4。
- **上行栅格属于一个区**（粘住）：见 §3.7。

M4 **未做**的：区数超过 4 时第 5 个区的锚点被跟踪但不可解（`ZONE_FULL` 诊断）；上位机仍无分区管理界面（见 §5 的 M5 条目）。

```
└───────────────────────────┬──────────────────────────────────┘

└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────┴──────────────────────────────────┐
│ L-1 平台/驱动层  decadriver(deca_device) · platform(SPI/port)   │
│                    Drivers/STM32L4xx_HAL · startup · system      │
└──────────────────────────────────────────────────────────────┘
```

分层规则（代码里实际遵守的）：

- **L0 是唯一真相源**。协议头里连"哪一字节是坐标的 x"都写死成 `DL_TS_COORD_IDX`；三个工程（anchor/tag/gateway）共用同一份 `shared/`。
- **L0 不含逻辑**，只有 `#define` 和纯数据结构。
- **L1 只依赖 L0**，不碰硬件，不含状态机 —— `tdoa_solver.c` 的入参是"锚点数组 + TOA 数组"，出参是"xyz + rms + 内点数"，可以脱机跑。
- **L2 持有全部状态**（`g_anchor`、`s_trackers`、`gw_devs`）。
- **L3 不做任何数值计算**，只做展示与编排；数值判定全在 L1/L2。

## 三、算法细节

### 3.1 TDMA 栅格（一切的时间基准）

| 量 | 值 | 出处 |
|---|---|---|
| 一槽 | 6.25 ms | `DL_SLOT_DTU_US 6250` |
| 一轮 | 8 槽 = **50 ms** | `DL_TIMESYNC_PERIOD_MS 50` |
| 一超周期 | 2 轮 = 100 ms | `DL_ROUNDS_PER_CYCLE 2` |
| 信标 / 解算频率 | **20 Hz** | `DL_SOLVE_INTERVAL_MS 50` |
| 槽 0 | 归本区参考锚点 | 网关下发的区时隙表（M3） |
| 最多锚点数 | 8 | `DL_MAX_TRACKED_ANCHORS 8` / `ANCHOR_MAX_SLOTS 8` |
| 名册上限 / 最小组网规模 | 8 / 3 | `NET_MAX_PARTICIPANTS 8` / `NET_MIN_PARTICIPANTS 3` |

时隙表**全网只有一张**，由网关在 NETWORK_START 里下发（**区的参考锚点占槽 0**，其余成员按名册顺序占槽 1、2、3…），成员各自 `tdma_build_table()` 反查成 `slot_owners[slot] = rank`，并按自己在名册里的下标取自己的槽（M3 取代了旧版的 `tdma_build_table_from_roster()` / `tdma_build_table_from_neighbors()` / `is_in_root_slot_table()`）。参考锚点在信标里公布这张表，成员只**检查**一致性，不采纳——表只有一个来源，就是网关。

成员入槽判据是"有没有拿到本区参考锚的 DS-TWR 修正"：没拿到就把信标的 `slot` 字节写成 **255**，标签据此排除它（M3）。**ALOHA 兜底已删除**——未入槽者不再抢信道发信，而是照常按栅格发但自报 255。成员超过 `DL_REF_STALE_MS`（3 s）收不到参考锚的信标就**停止发信**（`tdma_may_tx()`），因为在错的时基上发信会污染整轮所有锚点的 TDOA。

### 3.2 DS-TWR 路径修正（区参考锚侧解算，M3）

成员信标带三个量：`T2`（自身 TX 时刻）、`r1`（收到参考锚帧的 RX 时刻）、`refc`（该参考帧的 cycle id）。参考锚侧已知 `r2`（自己的 RX 时刻）、`T1`（自己那一轮的真实 TX 时刻，存于 `ZONE_REF_TX_HIST` 环形表）：

```
(r2 − T1) = prop_R→X + f·(T2 − r1) + prop_X→R
⇒ 2·prop = (r2 − T1) − f·(T2 − r1)
prop_child = prop_ref / f_ref          (换算到成员时钟单位)
```

要点：

- **T1 必须用参考锚的实测 TX 时刻，不能用标称栅格时刻** —— 否则参考锚自身的栅格误差会整段漏进解出的传播时延里。
- 合理性门限：单程 0.2 m ~ 100 m（`DL_TWR_CORR_MIN_DTU 40` / `DL_TWR_CORR_MAX_DTU 22000` DTU，1 m = 213.20 DTU）。
- IIR 平滑：`(old·3 + new)/4`，路径缓慢变化、测量有多径抖动。
- 参考锚每轮**一批**广播 `FUNC_TWR_CORR 0xE7`，每条 4 字节（rank u16 + corr_dtu u16），最多 8 条；新鲜度上限 `DL_TWR_CORR_MAX_AGE_CYCLES 2`（成员按同一 cycle 判定过期）。
- **区里的每个成员都直接跟参考锚做往返**，没有中间层：这是"区公共时间轴"能成立的唯一途径（见 §5 的"per-anchor 单程映射"那条设计约束）。

### 3.3 时钟同步（`shared/shared_data/clock_sync.c`，factor/offset 双状态）

模型：`global = factor × local + offset`，其中 `factor = 1.0 + cfo_raw / 67108864.0`（2^26，`CS_CFO_TO_FACTOR_DIVISOR`）。

- **滤波**：Kalman 形式，过程/测量噪声按 50 ms 节拍标定（`CS_DEFAULT_FACTOR_PROC_VAR 1e-13`、`CS_DEFAULT_FACTOR_MEAS_VAR 4e-12`），offset 走 RC（`CS_DEFAULT_RC_ALPHA 0.30`）。
- **率窗口**：16 样本滚动窗，至少 8 个才出率（`CS_RATE_WINDOW_SAMPLES 16` / `CS_RATE_MIN_SAMPLES 8`）。窗口用首尾两点算率，所以**单个坏帧能毒化整窗** → 前面加一层**样本级门限**（`cs_gate_check`）：候选样本的区间率必须落在窗口内区间率的 **中位数 ± 4·MAD** 内（稳健统计，不依赖滤波器状态，否则会死锁），否则直接丢弃（`CS_GATE_MIN_INTERVALS 3`）。
- **离群门限**：CFO 5 ppm（`CS_FACTOR_OUTLIER_CFO 5e-6`）、时戳 1 ppm（`CS_FACTOR_OUTLIER_TS 1e-6`）。
- **钳位**：预热后 factor 偏离 1 超过 **2 ppm**（`CS_FACTOR_CLAMP 2e-6`）就钳住；预热期（`CS_WARMUP_UPDATES 8` 次更新前）放宽到 50 ppm（`CS_FACTOR_CLAMP_WARMUP 50e-6`）。

### 3.4 槽补偿 TDOA 装配（`tag_solve_zone()`，全项目最核心的一段）

**M4：先按区聚类，再逐区解算。**

`tag_solve()` 不再直接解算，它先把 tracker 按 `zone_id` 分桶，然后对每个桶各调一次 `tag_solve_zone()`：

```
s_zones[DL_MAX_ZONES]        每个区一个桶（参考锚、时钟比、TDOA 基准）
  ↓
zone_set[zi] = 该区里"新鲜 + 未脱同步 + 有 zone_id"的锚点
  ↓
tag_solve_zone(zi, ...) → TagZoneFix { x,y,z,rms,q,flags,zone,n_valid }
  ↓
选一个区的结果发布（见下）
```

**为什么必须分桶**：两个**不同区**的锚点在两套不同的栅格、两个不同的时钟域里。它们的 TDOA 是几十米量级的"距离差"，能通过 ±150 m 的接受窗，却会把解拽到标签从未去过的位置。桶因此是**闭集** —— 参考锚、槽补偿、时钟比三者全部来自**同一个区**。

**"无区"不是桶**：`zone_id == DL_ZONE_ID_NONE` 的锚点没有已声明的栅格，放不上栅格，也就不参与任何解算。锚点仍然被跟踪（操作员在汇总里看得见），只是不参与几何。**行为变化**：只有无区锚点时，标签**不再输出任何位置**（以前会退化成锚点质心）。

**主公式**（每个区各算各的）：

```
toa_equiv = rx_local − slot × slot_dtu_eff − tx_err
slot_dtu_eff = DTU_PER_SLOT × slot_rate
DTU_PER_SLOT = DL_SLOT_DTU_US × UUS_TO_DWT_TIME = 6250 × 63898
slot_rate    = 标签时钟 / 本区参考锚时钟    (P1-4 独立通道估计，见下)
```

三个分支（都在**区内**进行）：

| 分支 | 条件 | 做法 |
|---|---|---|
| **区参考锚**（正常） | 本区参考锚在候选集里 | 每个锚的 `tdoa_avg`（在 RX 路径里与**同轮**本区参考锚的 TOA 配对后，做 8 轮滑动平均，`TAG_TOA_AVG_N 8` ≈ 0.4 s）→ `toa_dtu[0] = 0`，其余填相对 TDOA。**天然轮次一致，不需要 cycle 过滤** |
| **非区参考锚** | 本区参考锚不在集里 | 用绝对槽补偿 TOA（`rx − slot×slot_eff − tx_err`），再相减。不可平均 |
| **兜底** | 锚点 `slot == 255`（没被区参考锚确认） | 直接用原始 RX 时戳相减，**必须同轮**，且主导轮内不足 3 个锚点时放弃本轮（`TDOA_CYCLE_WAIT`） |

**发布哪个区**：

1. **粘住当前发布的区**，只要它还能解 —— 标签物理上只在一个地方，正常由一个区服务；跨区边界来回切会让位置无故跳变。
2. 否则取**解里有效锚点最多**的区，并列时取质量更高的。

**没有有效区 ⇒ 什么都不输出**：质量 = 65535、zone = `DL_ZONE_ID_NONE`、位置清零。**绝不输出锚点质心** —— 质心在地图上看起来像一个位置，但它不是。

**为什么必须减去 `tx_err`**：信标"瞄准"的栅格时刻与真正离开发射的时刻差两截 —— DX_TIME 寄存器只能表达 256 DTU（4 ns）整数倍，标称时刻被**向下取整**，信标最多早发 255 DTU ≈ **1.2 m 路径**；再加上器件 TX 管线时延 δ。所以每帧都要发布"出发误差"，且它必须是**偏差量（时长）而不是时间戳** —— 原始时间戳活在发送方时钟里，其 offset 吸收了 Root→子站的传播时延，跨锚点没法相减。

**为什么 `slot_rate` 要单独估**：时钟滤波器的 factor 会被离群门限拒绝更新，率就冻结了；而冻结的率正好是槽补偿最不能用的东西。所以标签另开一路（P1-4）：直接用相邻两帧**本区参考锚**信标的 `Δrx_local / Δtx_remote`，取最近 5 次的中位数，**每帧都更新**（不管滤波门限收没收）。接受区间 0.99~1.01。**每个区一份率**，绝不跨区共用。

**接受窗**：`|TDOA| ≤ 150 m`（`TDOA_MAX_PATH_M`）。

**候选筛选**：锚点必须同时满足 `slot != 255` **且** `coord_valid`。没有坐标的锚点贡献的是"到原点的距离"，会把整个解往 (0,0) 拽。

**循环一致性**：信标带 16 bit cycle id，一轮错位 = 50 ms = 3.19 M DTU，远超接受窗。区参考锚路径因为平均值本身轮次一致，不需要过滤；兜底路径**必须**过滤。

**tracker 过滤**：解算前先剔掉 `desynced` 的锚点和超过 `TAG_TRACKER_FRESH_MS`(250 ms) 没心跳的锚点。M4 起还要剔掉**没有 `zone_id`** 的锚点（放不上栅格）。本区的参考锚由桶直接给出（`s_zones[zb].ref_rank`），不再按 `score = quality×1000 − age_ms` 在候选集里挑 —— 挑出来的"最优"未必是本区的参考锚，跨区混挑会拿错时基。

### 3.5 位置解算（`shared/downlink/tdoa_solver.c`）

```
TDOA_cm[k] = (toa[k] − toa[0]) × 0.46907 cm/DTU   (CM_PER_DTU_F)
残差 res[k] = (r_k − r_0) − TDOA_cm[k]
雅可比 J = ∂(r_k − r_0)/∂x = u_k − u_0             (u = 单位方向向量)
正规方程 (JᵀWJ) Δ = −JᵀW res
```

- **Gauss-Newton**，最多 12 次迭代（`MAX_ITER 12`），收敛判据：步长 < 0.10 cm（`CONV_THRESH`）或 RMS 改善 < 0.02 cm（`CONV_DIFF_THRESH`）。
- **自适应阻尼**：残差上升 → 阻尼 0.3（`DAMP_FACTOR`），连续两次发散 → 0.15（`DAMP_DIVERGING`）。
- **离群剔除**（不是直接扔点，是降权）：`|res| > 3.0 × 加权RMS`（`OUTLIER_THRESH`）→ 权重 ×0.5，降到 0.1（`MIN_WEIGHT_KEEP`）以下才彻底剔除。
- **多起点**：上一帧解 + 锚点质心，各跑一次，取残差小的。上一帧解作种子是因为标签两轮之间只移动几厘米，比质心好得多；质心保留是为了防止一次坏解把迭代永久困在局部极小。3D 奇异时自动再跑一遍 2D（标签在锚点多边形内部时雅可比行近乎平行，正规方程病态，旧代码直接返回"无解"）。
- **z 可辨识性**（P2-10，最容易被忽略的一处）：

  ```
  z_info = H[2][2] / (H[0][0] + H[1][1] + H[2][2])
  ```

  这是**几何判据**，不是"锚点高度差"判据。旧判据是"所有锚点高度差 ≤ 1 cm"，但 1 cm 高差在 20 m 展布下 z 方向信息占比近乎为零，高度误差被放大 2000 倍。`z_info < 0.02`（`Z_INFO_MIN`）就判 z 不可辨识 → 该次 3D 结果作废，走 2D 兜底，高度报为"锚点平面高"并置 `Z_VALID = 0`。
- **2D/3D 选择**：`n < 5` 一律 2D（`use_2d`）。4 锚点恰好定解，带噪 TDOA 会被**精确拟合** —— 残差接近 0 而位置可以差 1 米（实测 5 cm TDOA 噪声 → 94 cm 位置误差）。5 个锚点才超定。
- **三道"不许出数"的闸门**（2026-11-24 审查轮新增，见 §5）：多起点的种子之一就是**锚点质心**，所以迭代一旦失败，结果就停在质心上；而"根本没动过"的拟合残差天然很小，质量分（由残差算出）反而会给它**好成绩**。三道闸门把这类失败从"出一个数"改成"拒绝出数"：

  | 闸门 | 判据 | 拦住的现场表现 |
  |---|---|---|
  | 锚点太少 | `n < 3` → `-2` | 2 个锚点只产生 1 个 TDOA，欠定；旧代码放行并返回**残差无穷大**的位置 |
  | 锚点重合 | 不同位置的个数 `< 3` → `-1` | 4 个锚点里 3 个站在一起 = 一个"戴了 4 顶帽子的 2 锚点系统" |
  | 几何病态 | 末次更新的正规方程奇异，或水平方向条件数份额 `< 0.010` → `-1` | 锚点与标签共线时，两个 TDOA 方程的梯度平行，步长消失：**解偏差 65 cm，残差却只有 2.8 cm** |

  另有**残差物理上限**：任何 TDOA 都不可能超过两锚间距，所以残差超过锚点最大间距（或非有限）即判 `-1`——旧代码会把残差 1e9 cm 的失败拟合当成位置发出去。
- **返回值**：`1` = 解出且高度有效；`0` = 解出但高度无信息（此时 z 只是占位）；`-1` = 几何撑不住这个位置（奇异/病态/锚点重合/残差越界）；`-2` 锚点不足（`< 3`）。
- **宿主端可执行验证**：`test/solver_host_test.c` 是本项目**第一个能在开发机上真正跑起来的测试**（求解器是纯计算，无 HAL/无射频）。实测：良好几何下误差 3~6 cm（受 DTU 量化限制）；退化几何下现在一律拒绝出数。详见 `docs/Zone_Mesh_Plan_Review.md`。

### 3.6 质量分（0..1000，越大越好）

```
q_r   = 1000 × clamp(1 − rms_cm/50, 0, 1)      残差项：0 cm→1000, 50 cm→0
q_n   = 1000 × n_inlier / n_meas                 内点率项
q_red = 500 (≤2 测) / 750 (3 测) / 1000 (≥4 测)  冗余项
q     = q_r × q_n × q_red / 1e6
```

`q_red` 的存在理由：3 锚点网络是**恰好定解**，残差天然接近 0，但位置可能差一米 —— 光看残差会给出虚高的分，所以冗余不足要主动打折。

`n_inlier` 的定义（2026-11-20 代码审查轮更正）：**未被离群剔除判据标记**的测量数。残差超过 `OUTLIER_THRESH` 的锚点权重降到 0.5，它仍然参与拟合，但**不再计入内点数** —— 否则「内点率」会在刚判出离群时仍报 100%，质量分恰好在最不该乐观的时候乐观。

`65535` 是"无解"标记（`DL_POS_QUALITY_NONE` / `TAG_REPORT_QUALITY_NONE`），不是质量值。

**标签的 flags**（26 字节帧的 [20]）：

| 位 | 名称 | 含义 |
|---|---|---|
| 0x01 | `DL_POS_FLAG_Z_VALID` | 高度是**测出来的**，不是锚点平面高 |
| 0x02 | `DL_POS_FLAG_SOLVE_VALID` | 位置是新鲜解 |
| 0x04 | `DL_POS_FLAG_3D_SOLVED` | 解算确实按 3D 跑的 |
| 0x08 | `DL_POS_FLAG_DEGRADED` | 标签活着但**没有网络** |

[21] 是残差毫米数（`DL_POS_RMS_MM_MAX 255` 饱和）。

### 3.7 上行栅格与保护窗（标签怎么发）

正常上报必须落在**槽 0 的保护窗**（区参考锚信标之后、槽 1 信标之前的空档），否则会压到基站信标上 —— 既破坏那个基站自己的接收，又污染标签自己的 TDOA。

```
目标时刻 = guard_hw + TAG_REPORT_DELAY_US(3000) + ALOHA 抖动(0..1200 µs)
          ⇒ 落在 6.25 ms 槽的 3.0~4.2 ms 处，余量 2.05 ms
```

标签**自己维护一条 50 ms 栅格**（`s_guard_hw` / `s_uplink_ms` / `s_last_tick_ms`），相位锁在**区参考锚**信标上：信标纠正相位与保护窗起点，**丢一个信标就在标签自己的 device-time 域外推 50 ms**（率误差 20 ppm × 50 ms = 1 µs，远小于 6.25 ms 槽）。所以"丢一个信标"不等于"标签哑一整轮"。

**M4：上行栅格属于唯一一个区（粘住）。**

保护窗是参考锚的栅格。用 A 区的栅格发 B 区的位置，会正好压在 A 区某个锚的信标上 —— 破坏那个锚的接收。所以上行区是**粘住**的（`s_uplink_zone`）：只有当前区的参考锚静默超过 `TAG_ROOT_TIMEOUT_MS`（2 s）才交给另一个区。在区边界同时听到两个区参考锚的标签**留在它正在发布的那个区**，交接是一次性、干净的。

没有 `zone_id` 的参考锚信标**不定义栅格**，直接忽略 —— 没有区就没有栅格，标签退回降级路径，直到有区的参考锚出现。

延迟发送失败时重试 2 次、每次提前 200 µs（`TAG_TX_RETRIES 2` / `TAG_TX_RETRY_STEP_US 200`），实在不行退即时发送 —— 但只在保护窗还开着时才发，宁可丢帧也不污染测量。

### 3.8 降级与保活（三态可区分）

| 状态 | 判据 | 行为 |
|---|---|---|
| 正常 | **任一区**的参考锚在 2 s 内有心跳 | 20 Hz 位置帧 |
| 降级 | 所有区的参考锚都静默 > `TAG_ROOT_TIMEOUT_MS 2000`，但**其他**锚点还在 | 收到任何信标后立刻发一帧降级报告，2 Hz（`TAG_DEGRADED_REPORT_MS 500`），帧带 `DEGRADED 0x08`、quality = 65535 |
| 静默 | **全网**静默 | 之前会彻底哑掉 → 已加本地保活：`TAG_ALIVE_KEEPALIVE_MS 1000`，1 s 内没有任何上行发出就补发一帧降级报告 |

"标签还在但没位置"和"标签断电了"必须在地图上可区分 —— 保活就是为这个。当前实现里标签只发**解算结果**，不上报原始时戳，所以没有多标签上行调度（用户已明确：标签的消费者是机器人，UWB 上行只用于调试地图）。

**不变量**：降级上报不能只依赖「收到信标」—— 全网静默时没有任何信标可依赖，必须有本地兜底。

### 3.9 seq 单一来源与丢包统计

- `s_report_seq++` 只在 `tag_report_publish()` 里加一次（每轮一次）。**一帧只构一次**（`s_report_buf`），UWB 帧和本地 ASCII 行**从同一批字节渲染**，两者不可能说不同的话。
- 网关侧算模 256 的 seq 跳变：跳变 > 1 且 ≤ `GW_POS_MAX_GAP`(64) 才算丢包；**排除 DEGRADED 帧及其后一帧**（降级时是故意降速，不是丢包）；输出 `+POSMISS,<uid>,<本次丢>,<累计丢>`。

**已知偏差（未修）**：seq 在**解算栅格**（绝对 50 ms）上递增，而无线电上行跑在**锁 Root 的 50 ms 栅格**上，两者会缓慢相对漂移，于是帧里带的 seq 偶尔跳 2（网关误算 1 丢）或跳 0（网关 `pos_rx` 少计，但 `+POS` 仍会输出）。统一两者需要动延迟发送的时序，无硬件验证前不值得冒险。

### 3.10 组网状态机（网关侧，非阻塞）

```
GW_NETSTATE_IDLE(0) → STARTING(1) → WAIT(2) → RUNNING(3)
```

`AT+NETSTART=<root_rank>,<r1>,<r2>,...`：

- **名册是强制的**（P2-12）。没有名册直接拒绝并回 `+NETSTART_ERR,NOROSTER` —— 旧版会退化成"Root + 网关恰好认识的所有基站"，把操作员没选的基站悄悄拉进网络，而没坐标的基站会把 TDOA 解拽向原点。
- 网关**连续 2 s、每 20 ms 广播一次** `0xE8 NETWORK_START`（`GW_NETSTART_BURST_MS 2000` / `GW_NETSTART_PERIOD_MS 20`），**不阻塞**：广播在主循环里跑，ACK 走普通 RX 路径（所以不会丢帧）。
- 输出三个语义分开的行：

  | 行 | 含义 |
  |---|---|
  | `+NETSTART_OK,<ack_cnt>,<root>,<miss_cnt>,<miss名单…>` | 谁**回过话**（ACK） |
  | `+NETGRID,<on_grid_cnt>,<roster_n>` | 谁**真的在栅格上**（信标里 slot ≠ 255 的成员）。burst 刚结束时通常是 0，**不能**读成"组网成功" |
  | `+NOCOORD,<ranks…>` | 名册里已知没坐标的基站。**是警告不是拒绝**（它们会被标签自己从解算里剔掉） |

- 按钮状态由上位机的 `net_phase()` 驱动，**不由 `+NETSTART_OK` 驱动**：收到 OK 只置"组网中 n/m"，只有轮询到 phase == RUNNING 才显示"✓ 组网成功"。名单不全时**绝不**显示成功。

### 3.11 坐标有效性传播

一个基站**没有坐标**对解算的伤害是隐蔽的：TDOA 是距离差，没坐标的锚点贡献的是"到原点的距离"，把解整体往 (0,0) 拽。所以有效性必须一路带着走：

```
Anchor 收到 0xF4 COORD_WRITE → s_coord_valid = 1
   → 信标 flags 置 DL_TS_FLAG_COORD_VALID(0x08)
   → 标签据此决定该锚点能否进解算（不能的仍留在表里，操作员要看得见是谁）
   → 网关从信标学到状态 → 输出 +COORDSTAT
   → 网关回读 0xE1 → 0xE2，读 ackbuf[16] 的 valid 位
   → 网关 gw_set_coord_state() 记账
```

注意 `s_coord_valid` **不从 flash 保存结果推导**（flash 现在是 stub），所以"存过"和"有效"是两件事。

### 3.12 平台层的一个硬约束：DW3210 尾 2 字节损坏

DW3210 通过 SPI 读回的帧，**最后 2 字节会被损坏**。因此：

- **每一帧都以 `0xCC 0xDD` 吸收垫结尾**。
- 所有 `frame_len` 检查都是**下限**：`DL_TIMESYNC_MIN_LEN 63`（兼容老固件的 63 字节信标）、`DL_TIMESYNC_LEN 67`。
- 位置帧 `[22..23]` 是垫，`flags` 在 [20]、`rms_mm` 在 [21] —— 都在垫**之前**，这样才安全。
- 信标里 `rx_ref_cycle` 必须留在 [61..62]（垫在 [65..66]）—— 早期版本垫放在帧中部、活数据在尾部，Root 的 DS-TWR 永远合不上。

### 3.13 TDMA 在遮挡 / 失联下的行为（鲁棒性分析）

**核心前提：这套 TDMA 是「开环 + 绝对时刻」的。**
每个槽的发送时刻是各站**自己算**出来的，然后写进 DW3210 的延迟发送寄存器（`dwt_setdelayedtrxtime()` + `dwt_starttx(DWT_START_TX_DELAYED)`，`fusion_anchor.c:1345`）。**发送时刻不依赖「这一轮有没有收到信标」**，所以「遮挡 → 乱发」这条因果链在代码里不成立：丢一个信标只会让这一站少一次参考刷新，它仍然在自己的槽里发。

- 区参考锚点：`s_zone_grid_base + k*period`（`tdma_grid_target()`），k 是自己数的整轮数。
- 区成员：`g_tdma_ref.base_origin + k*period_local + slot_off`，其中 `k = (now − base_local_time)/period_local` —— **按整轮外推**，不是「收到就重发」。

**已有的「宁可不发也不乱发」：**

| 机制 | 位置 | 行为 |
|---|---|---|
| 3 s 收不到区参考锚信标 → 停发 | `tdma_may_tx()`，`DL_REF_STALE_MS 3000` | 成员**拒绝发信**（宁可不发也不发在错时基上）；参考锚点自己不受此限（M3 取代了旧的「5 s 收不到 Root 槽表 → 退网」，因为时隙表现在由网关一次性下发，不再需要每轮从参考锚那里收） |
| TWR_CORR 超 2 轮未刷新 → 退网 | `fusion_anchor.c:2359` | `anchor_clear_slot("TWR_CORR_STALE")` |
| 离栅格帧标记 | `fusion_anchor.c:1197` / `:1370` / `:1051` | `slot = 255` + `DL_TS_FLAG_TX_OFFGRID` → 标签不把它们进 TDOA |
| Root 的 TWR_CORR 立即帧 | `anchor_twr_corr_poll()` | 紧跟 Root 自己槽 0 的信标发，仍在槽 0 窗口内，撞不到子站 |
| 标签上行保护窗 | `fusion_tag.c:1665` | 落到槽 1 上就**跳过这一帧**（`s_n_report_skip++`），宁可丢帧不污染测量 |
| 标签解算新鲜度 / 锚点数 | `fusion_tag.c` | 250 ms 没听到的锚点剔出；< 3 个锚点直接不解算 |

**真正的风险不是碰撞，是精度。**
`fusion_anchor.c:2225` 的设计注释：「用本地 RX 时刻做栅格原点，让率误差只作用在『距上次参考经过的时间』上（< 一个 TDMA 轮），栅格放置误差 ≈ 40 ms × Δf ≈ 40 ns @1 ppm。」

这个 40 ms 的界**只在参考锚的信标每轮都到时才成立**。参考锚→成员断掉后 `base_origin` / `base_local_time` 不再刷新，成员按 `k*period_local` 继续外推：

```
放置误差 = 失联时长 × Δf
1 ppm → 1 µs/s → 1 µs = 127.9 DTU × 0.469 cm ≈ 60 cm/s 的路径等效漂移
失联 1 s → 0.6 m      失联 3 s（DL_REF_STALE_MS 守卫触发）→ 1.8 m
```

而标签用的是**槽补偿**：标签不信信标里广告的 TX 时戳，用 `toa = rx_local − slot × 6.25 ms`（`fusion_anchor.c:295` 的注释明说「The Tag does NOT use the advertised TX stamp」）。所以成员的栅格放置误差对标签是 **1:1 的 TDOA 偏置**，标签无法区分「基站晚了」和「传播路径变了」。

⇒ **参考锚→成员遮挡 ⇒ 该成员在 3 秒内向标签贡献一个从 0 涨到 1.8 m 的偏置；第 4 秒它停发，标签反而恢复正常。故障最严重的窗口是停发之前那 3 秒。**

参考锚侧的栅格残差诊断（`GR,<rank>,<cm>`）已经算出了这个量，但**只打印、不动作**。

**碰撞风险的真实来源（都不是「遮挡导致乱发」）：**

1. ~~ALOHA 兜底~~ —— **M3 已删除**（无 ALOHA、无 `NET_ALOHA_RETRY_MS`、无 `NET_STARTING`/`NET_WAIT_CONFIRM`）。未入槽的成员改为**按栅格发但自报 `slot=255`**，标签据此排除它 ⇒ 不再抢信道，也就没有这类碰撞。
2. 延迟发送失败回退（`fusion_anchor.c:1358`）：写寄存器失败 / HPDWARN → 立即发送，而此时距目标还有 ~4 ms（`ANCHOR_TX_LEAD_US 4000`）→ 提前量 4 ms > 半槽 3.125 ms → **落在前一个槽的窗口里**，真碰撞。内容已标 `TX_OFFGRID`，但空口时间仍然撞。
3. 发现心跳（`fusion_anchor.c:2940`）：也是立即发，但只在 `!tx_armed` 时发；正常运行中 `tx_armed` 恒真 → 很少触发。组网阶段锚点本就不在栅格上发 → 不冲突。
4. 网关：完全无同步，但 NETSTART 突发发生在锚点还没上栅格时；OTA 期间锚点的栅格发送被 `!gw_ota_is_active()` 抑制（`fusion_anchor.c:2880/2907/2924/2940`）→ 不撞。
5. 标签↔标签：0..1200 µs 的 LFSR 抖动塞在 ~2.05 ms 的窗口里，多标签必然互撞；但都落在槽 0 保护窗内，不影响锚点信标的接收。

**断的是哪一段，后果不同：**

| 断的是哪一段 | 后果 |
|---|---|
| 区参考锚 → 成员 | 成员按外推继续发 3 s（精度塌，见上），3 s 后停发；参考锚的邻居表不过期，链路恢复后成员重新收到参考锚信标即自动回槽 |
| 成员 → 参考锚（单向） | 参考锚仍会**继续广播**该成员的旧 corr（`anchor_twr_corr_poll` 里 `L->have` / `corr_valid` 从不超时失效），而成员每轮收到自己的条目就把 `s_twr_corr_cycle` 刷成当前轮 ⇒ **`TWR_CORR_STALE` 守卫实际上不会触发**，成员带着一份很旧的路径修正继续在栅格上发 |
| 区参考锚挂掉 | 区内全部成员 3 s 内停发静默；标签 2 s 后转降级（2 Hz），全网静默时 1 s 本地保活 → 地图上标签「活着但没位置」。**该区完全失去定位能力**（每区单参考锚 = 单点故障，见 §5） |
| 标签 ↔ 某些锚点 | 该锚点 250 ms 后剔出解算；< 3 个则不解算；≥ 3 个则质量分按内点率 / 冗余打折 |

**空白（已记入 §5）：** 无 MAC 层 CCA / RTS-CTS / ACK；无基于链路质量的准入；栅格残差只诊断不动作；每区单参考锚（单点故障）；缺「失去参考后的精度守卫」（只有 3 s 的硬停发，没有中间态的降级）。

### 3.15 误差预算：晶振规格 ≠ 频率比误差（更正一处记账错误）

TDOA 是**差分量**，它需要的只是"锚 A 的钟"与"锚 B 的钟"之间**比值**的准确度，不是各钟相对理想频率的绝对精度。

$$\Delta t_{\text{TDOA}} \supset \Delta f_{\text{ratio}} \times \Delta t_{\text{span}}$$

- 两枚芯片**各自**相对理想频率偏 20 ppm（晶振规格）—— **与 TDOA 无关**；两枚都偏 20 ppm 的钟，对 TDOA 的贡献是 0。
- 进入误差的是 $f_A/f_B$ 这个**比值**的估计误差。本项目里它是**实测**出来的：
  - 锚侧 `clock_sync.c` 的 `cs_rate_measure()`：16 样本 × 50 ms = **800 ms 窗口**，注释自述 ≈1 ppb；
  - 标签侧 `fusion_tag.c` 的 `s_root_rate`：**5 个单轮（50 ms）比值的中值** ≈ 250 ms 窗口 → ≈1–2 ppb（**待实测**）。

**因此把 20 ppm × 龄期 代进误差预算会高估约 10 000 倍。** 按 1–2 ppb × 0.47 s（`CS_REF_MAX_AGE_DTU`）算，频率比项是 **3–28 cm**，不是 2.8 m。

真正的主导误差项是这三类（本项目**均未量化**）：

| 来源 | 性质 | 现状 |
|---|---|---|
| **DS-TWR corr 陈旧** | `corr_dtu` 不带测量龄期，子站收到广播就刷新鲜度 ⇒ 龄期实际无上界 | §5「`TWR_CORR_STALE` 守卫实际不触发」 |
| **corr 的半程假设偏置** | `2·prop = (r2−T1) − f·(T2−r1)` 求出的是 `(prop_R→X + prop_X→R)/2`，逐链路的 TX/RX 硬件不对称直接变成**常数偏置** | 未标定 |
| **天线延迟 / TX 延迟标定残差** | 逐锚常数偏置，1:1 进 TDOA | 未标定 |

> ⚠️ 常见误用：`CS_FACTOR_CLAMP 2e-6` 是**每次更新的校正步长上限**（`clock_sync.c`：`applied = clamp(innovation, ±clamp)`），**不是"接受带宽"**，稳态下走的是时间戳速率（≈1 ppb）而非 CFO。收紧它只会让**收敛变慢**，不会提升精度。

## 四、上位机（`uwb_gateway_py/uwb_host.py`）的业务层要点

- **ID 冲突保护**：设备按 uid 单一键存储，若标签 id 与基站 rank 的 CRC16 撞上（16 标签 × 8 基站 ≈ 2%），`handle_pos` **绝不**把标签位置写进 `type == ANCHOR` 的记录（早期版本会把基站画到标签位置上）。
- **离群门限**：`OUTLIER_MIN_M 0.5` / `OUTLIER_SPEED_MPS 3.0`，质量分档 `Q_GOOD 700` / `Q_OK 400` / `Q_OUTLIER 300`。
- **无解帧（q ≥ 65535）** ⇒ 不做平滑、不延长轨迹，只标记 no-fix。
- **z 无效时**地图显示 `~` 而不是伪精确的平面高。
- **地图语义**：未组网的基站返回 `"idle"` 并单独用灰/虚线样式 —— 早期版本返回空串，和 RUNNING 落进同一个颜色分支，"没组网的基站"和"运行中的基站"在地图上长得一模一样。
- **持久化**：`anchor_cfg.json` 存 coords / labels / counter / tag_labels。
- **UART**：921600-8N1（固件与上位机两侧一致）。16 标签 20 Hz 的 `+POS` 负载约 10.2 kB/s ≈ 链路 11%，不是饱和。

| 标签侧率估计窗口 | 标签用单轮 50 ms 估 Root 率（≈20 ppb），基站用 800 ms 窗（≈1–2 ppb）—— 标签是槽补偿的**弱环**，属精度项，未做 |

| P2-1（solver 内部改 int64 绝对时戳） | 当前三个分支各自内部自洽，**是脆弱点不是现存 bug**，已记录为延后 |
| P2-2（噪声喂进 GN 权重） | 噪声目前只影响参考锚选择与质量分，未进 `weight[]`；用户已接受延后 |
| P2-3（3 锚病态） | 已用 `q_red = 500` 主动打折 + `n<5 → 2D`，不改代码，已记录 |
| P2-4（解算栅格与上行栅格错拍） | 解算用绝对 50 ms 栅格，阻塞会掉解算但不会错位；不改，已记录 |
| seq 与上行栅格相对漂移 | 已记录（§3.9），修它要动延迟发送时序 |
| 遮挡 / 失联鲁棒性 | 见 §3.13。**不是碰撞问题，是精度问题**：区参考锚→成员断后，成员按外推继续发最多 3 s（M3 把守卫从 5 s 收到 `DL_REF_STALE_MS 3000`），放置误差按 `失联时长 × Δf` 增长（1 ppm → 60 cm/s，3 s → 1.8 m），而标签用槽补偿 ⇒ 该误差 1:1 进 TDOA，标签检测不到。**故障最严重的窗口是停发之前那 3 秒** |
| `ROOT_SCHEDULE_STALE` 门限 5 s | 过长。§3.13 里正常态的放置误差界是 40 ms（1 轮），5 s 守卫把最坏偏差放到 3 m。缩到 200~500 ms，或让子站在失去参考后改发 `slot=255 / TX_OFFGRID`（标签排除），即可把最坏偏差压到厘米级。**M3 已删除该机制**（时隙表改由网关一次性下发，成员不再每轮从参考锚那里收槽表），代之以 `DL_REF_STALE_MS 3000` 的硬停发守卫（最坏偏差从 3 m 降到 1.8 m）。**中间态降级仍未实现** |
| `TWR_CORR_STALE` 守卫实际不触发 | 语义自相矛盾：Root 的 `L->have`/`corr_valid` 从不超时失效（仍广播旧 corr），而子站每收到自己的条目就把 `s_twr_corr_cycle` 刷成当前轮 ⇒ age 永远是 0~1。子站→Root 单向断时，子站带着很旧的路径修正继续在栅格上发。**未修** |
| 无 MAC 层 CCA / RTS-CTS / ACK | 全项目 grep 不到 CCA。两帧同时上电就同频互毁，只靠时隙错开 |
| 无基于链路质量的准入 | 唯一的链路测量（DS-TWR 路径延迟）只用于时间修正，不用于「要不要让这个锚点进解算」。遮挡严重的锚点照样进解算、照样贡献噪声 |
| ALOHA 无随机退避 | 所有未确认的子站 500 ms 齐步立即发送，彼此撞、也撞进别人的栅格槽。**M3 已删除整个 ALOHA 机制**（无 `s_aloha_mode` / `NET_ALOHA_RETRY_MS` / `NET_STARTING` / `NET_WAIT_CONFIRM`），本条**已销案** |
| 栅格残差只诊断不动作 | Root 侧的 `GR,<rank>,<cm>` 已经算出了每个邻居的栅格残差，但只打印不动作；把它变成准入条件（超阈值就踢出槽表）是一个近乎零成本的保护。**未实现** |
| DS-TWR corr 的**半程假设偏置** | `2·prop = (r2−T1) − f·(T2−r1)` 求出的是 `(prop_R→X + prop_X→R)/2`，逐链路的 TX/RX 硬件不对称会变成 `corr_dtu` 的**常数偏置**，1:1 进 TDOA。未标定。**未修**（见 `docs/UWB_TDOA3_Optimization_Plan_v2.md` §3.5 / §5.5.2） |
| 频率比误差的记账曾被高估 ~10 000 倍 | 曾按「晶振 20 ppm × 龄期」估误差，得 2.8 m。TDOA 只需**两钟之比**，而该比值是实测的（锚侧 800 ms 窗口 ≈1 ppb），频率比项实为 3–28 cm。**已更正**，见 §3.15。真正的误差大头是 corr 陈旧 / corr 偏置 / 天线延迟标定 / 多径 |
| 「per-anchor 单程映射」给不出绝对 TDOA | `clock_sync` 的参考对 `(ref_tx, ref_rx)` 会把该参考帧的**传播时延吸收进映射常数项**（参考帧上恒有 `M(ref_tx) = ref_rx`，而真值应是 `ref_rx − d/c`）。于是 `rx_A − M_A(tx_A)` = **路径长度的变化量**而非路径长度 ⇒ 每帧各自刷新参考时 TDOA ≈ 0 ⇒ **精确复现「输出恒等于质心」**。绝对 TDOA 只能来自①公共时基②锚↔锚往返测量③有线公共参考。**这是设计约束，任何改动不得违反** |
| **NETWORK_START 帧从不匹配（组网 100% 失效）** | 锚站把 `FUNC_NETWORK_START`(0xE8) 和 `FUNC_TWR_CORR`(0xE7) 用**同一个头模板** `match_twr_corr` 匹配，而该模板的 byte9 是 0xE7；`match_header()` 只跳过 SN/DST/SRC，**byte9 是要比的** ⇒ 网关广播的 0xE8 帧匹配失败 ⇒ `handled=0` ⇒ `anchor_process_rx()` 根本不被调用 ⇒ 锚站从不回 NETWORK_ACK、Root 永不起网。**已修复**（2026-11-20 代码审查轮）：为 NETWORK_START 单独建模板 `match_network_start`（dst=0xFFFF 广播） |
| 网关侧两处实现偏差 | ①`AT+RESET` / `AT+OTA_END` 的回显用**无界** `fmt_str()` 把命令尾部整段拷进 `char ack[32]` / `char out[32]`，而 UART 行缓冲最长 600 字符 ⇒ 一条 `AT+RESET=AAAA…` 就能写穿约 590 字节栈 ⇒ **栈破坏 + HardFault**，只需一条脏串口行即可触发。②`FUNC_DL_POS_REPORT` 分支只保证 10 字节帧头，却无条件读 `[10..17]` 当作 x/y/z/q ⇒ 截断帧被当成**有效坐标**上报，上位机照着画、照着平滑。**两项均已修复**（2026-11-20 代码审查轮）：回显改用有界 `fmt_str_n()`；位置报告增加 `len >= GW_HDR_LEN + 8` 的长度门限，不足即整帧丢弃。另外 `+POS` 现在**始终**追加 flags 与 rms（原来只在新版标签时追加），否则尾部 seq 会被上位机当成 flags（seq=1 看起来像 `Z_VALID`） |
| 上位机侧两处健壮性缺陷 | ①`poll_serial()` 的定时器重新装载写在 `process_rx()` **之后**，任何一行脏数据（截断的 `+POS`、缺字段的 `+NETSTART_OK`）抛出的异常都会跑出回调 ⇒ **轮询永久停止**：画面冻结在最后一帧，RX 队列无限增长直到进程死。②设备 `type` 会在两个设备撞 id 时在 ANCHOR/TAG 之间翻转，而 `handle_pos()` 的护栏、`on_dbl_click()`、`draw_links()`、绘制分派都是按**当前** type 判断 ⇒ 护栏能被"说服"，标签坐标被写进基站记录，基站被画到标签位置、真实坐标反而不画。**两项均已修复**（2026-11-20 代码审查轮）：`poll_serial()` 用 try/except 包住并**总是**重新装载定时器，各处 float/int 解析单独加保护；新增**粘性** `is_anchor` 标志（首次见到是基站就置位）与 `is_anchor_device()` 统一判定 |
| 标签侧三处实现偏差 | ①`TSUM` 汇总行用无界 `sprintf` 写 288 字节栈缓冲，8 个锚点 + 10 位龄期即溢出；`RX_RAW` 行同理（约 115 字节写进 96 字节）⇒ **栈破坏**。②位置报告 `[21]` 名为 `rms_mm`（毫米）但写进去的是**厘米** ⇒ 网关/上位机把 5 cm 读成 5 mm，**差 10 倍**。③原始 RX 兜底路径只要求**参考锚**离栅格，被测锚点不限制 ⇒ 上槽锚点（Root 的 slot 0）被混进裸 RX 相减，其 `tx_err`（最大 255 DTU ≈ 1.2 m）变成伪 TDOA。**三项均已修复**（2026-11-20 代码审查轮）：缓冲改为有界 `snprintf` + 扩容；残差改按毫米换算（32 位乘法）；兜底路径只允许 `slot==255` 的锚参与 |
| 2026-11-20 代码审查轮 | 全量静态审查（锚站 / 标签+求解器 / 时钟同步+协议 / 网关+上位机 四路并行）的完整结果见 **`docs/代码审查报告.md`**：§一 11 项**已修复**（对应本表上方的各行）、§二 16 项**未修复待办**（含位置、后果、优先级）、§三 复核中被推翻的前提。**本轮未编译、未烧录、未上机**，"已修复"只代表通过主机端桩语法检查 |
| 求解器四个"自信地输出错误答案"的洞（2026-11-24） | ①`n < 2` 放行 2 锚 ⇒ 欠定，输出**残差无穷大**的位置；②锚点**重合**不判（4 锚里 3 个站一起 = 2 锚系统）；③2D 正规方程**奇异**时用岭正则（+1e-3）继续 ⇒ 步长消失、**解停在种子（= 质心）**，却带着 2.8 cm 的小残差发出去；④残差无上限检查（1e9 cm 也照发）。**四项均已修复**（2026-11-24 轮，见 §3.5 的三道闸门），新增 `test/solver_host_test.c` 做宿主端实测 |
| 「质心禁令」在求解器内**不可实现**（2026-11-24 轮结论） | "4 锚正方形 + TDOA 全 0" 这一组输入，与"标签**恰好**站在质心"这一组输入**完全相同**，求解器输出必然相同 ⇒ 靠"解像不像质心"来判会误杀合法解。**判别只能放在知道测量来路的标签层**（M4 的硬性验收项）。宿主端已复现该输入（解出质心、残差 12.6 cm ⇒ 质量分给高分） |
| 槽补偿误差的量化（2026-11-24 轮实测） | 标签 `toa = rx − slot × 6.25 ms` 用的速率估计若差 d ppm，**一个槽**就是 6.25 ms × d ppm 的路径误差，且 TDOA 误差**随槽号线性增长**。实测（4 锚正方形按槽号排列）：每槽 10 cm → 位置偏 **14 cm**；每槽 375 cm（= 20 ppm，标签单周期速率估计的量级）→ 位置偏 **7.9 m**、残差 229 cm。**标签侧速率估计精度就是定位精度的主项** |
| 量纲常量重复定义（2026-11-24 M1） | `downlink_protocol.h` 曾自带一份 `TDOA_CM_PER_DTU 0.46907f`，与 `shared_defines.h` 的 `CM_PER_DTU_F` 是**同一常量的两份拷贝**，且 `TDOA_CM_PER_DTU` 全工程无人使用。**已修**：`downlink_protocol.h` 改为 `#include "shared_defines.h"`，`TDOA_CM_PER_DTU` 变成指向 `CM_PER_DTU_F` 的别名；`test/solver_host_test.c` 里那份本地拷贝也换成 `CM_PER_DTU_F`。现在 DTU↔cm 的数字**只有一处** |
| 区网格字段已上线但**尚未生效**（2026-11-24 M2） | M2 只把"区"这套字段**铺到协议和线路上**：NETWORK_START 带 zone_id / 区时隙表 / 时基，NETWORK_ACK 带 zone_id / 参考锚点，信标带 zone_id / 链路质量 / 区角色 / 参考时钟，位置报告带 zone_id。但**解算逻辑一行没改**：标签仍然只认一个 Root、仍然把从任意锚点收到的 TDOA 装进同一个解算，`s_solve_zone` 目前恒为 `DL_ZONE_ID_NONE`（除非所有用到的锚点恰好同区）。时隙表虽然改由网关下发，基站**实际发信的时刻仍按旧的 Root 栅格算**（`s_root_grid_base` / `root_tx_ts_for_cycle()` 还在）。**M3（去 Root 化）已让**基站侧的区字段生效**（`s_zone_grid_base` / `zone_ref_tx_ts_for_cycle()` 取代旧路径），但标签侧仍待 M4（按区分桶解算）**。**M4 已实现该部分**（见下方 M4 条目）。另外网关目前**编不出有意义的 `zone_time_base`**（各站时钟不同源），该字段连同 NET_FLAG_ZTBASE_VALID 一起保持清零 |
| 位置报告帧长从 24 → 26 | `zone_id` 落在 [22]，尾部 pad 跟着后移到 [23..24]。旧标签（22 字节）仍被网关接受，`zone` 读成 `DL_ZONE_ID_NONE`；上位机 `+POS` 的新字段**追加在末尾**（第 10 个字段），旧解析器不受影响 |
| **M3：区参考锚点由网关指定，锚站不自行切换** | 方案原文要求"按链路质量选参考锚 + 迟滞切换"。M3 **只做了前半句的替代方案**：参考锚由网关按上位机的 `AT+NETSTART=<root_rank>` **指定**，锚站**不做单方面切换**。原因：单方面切换会把那台锚站换到另一条时间轴上，它与区内其他锚点的槽补偿 TDOA 立刻失效；换参考必须是**全区的、一次性的、由上位机发起**的事件（换参考 = 换网关下发的区时隙表与参考锚字段）。质量门限 `DL_REF_QUALITY_MIN 60` / 迟滞 `DL_REF_SWITCH_HYSTERESIS 15` 已定义但**未使用**。**未实现** |
| **M3：每区参考锚是单点故障** | 参考锚静默 > `DL_REF_STALE_MS`（3 s）时区内成员**停止发信**（宁可不发也不发在错时基上），该区**完全失去定位能力**，而不是退化成"精度略降"。参考锚上电/被遮挡/断电 ⇒ 整区瘫痪。缓解手段（区内冗余参考锚 + 选举）**未实现** |
| **M3：`zone_time_base` 仍未收敛** | 网关的 `zone_time_base` 字段仍**全零**、`NET_FLAG_ZTBASE_VALID` 仍**清零**：网关与各基站不在同一时基上（每颗 DW3000 上电从 0 起算），在没有成员公布参考之前网关编不出有意义的时基。区公共时间轴目前只存在于**每个成员本地**（成员自己收参考锚的信标、记 `zone_ref_ts`、用它校自己的栅格），**没有一份全网共享的时基**。协议里为此预留的 `FUNC_ZONE_SYNC_REQ/RSP`（0xEA/0xEB）**未实现** |
| **M3：标签侧仍是单 Root 模型** | 锚站已经去 Root 化，但**标签还没改**：`fusion_tag.c` 仍按 `rx_buf[DL_TS_LEVEL_IDX] == 0` 识别"参考锚"，仍把从不同区来的 TDOA 装进同一个解算，`s_solve_zone` 仍恒为 `DL_ZONE_ID_NONE`。**M4（按区分桶解算、每区单独解算、无有效区不出结果）才让区的概念真正生效** —— **M4 已实现，见下方 M4 条目** |
| **M4：标签侧按区聚类解算** | `fusion_tag.c` 重写：`TagZoneBucket s_zones[DL_MAX_ZONES 4]` 每区一个桶（参考锚 / 时钟比 / TDOA 基准），`tag_solve()` 先按 `zone_id` 分桶再逐区调 `tag_solve_zone()`；跨区的 TDOA **不配对**，锚换区时清空其 `tdoa_avg`。**没有有效区 ⇒ 不出位置**（quality=65535、zone=0xFF），**绝不输出质心**。**行为变化**：以前"只有无区锚点"会退化成质心输出，现在一律不出位置 |
| **M4：上行栅格属于唯一一个区（粘住）** | 保护窗是参考锚的栅格，用 A 区的栅格发 B 区的位置会压到 A 区锚点的信标上。上行区 `s_uplink_zone` 因此粘住：只有当前区参考锚静默 > 2 s 才交接。在区边界同时听到两个区参考锚的标签**留在正在发布的那个区** |
| **M4：区数上限 4，第 5 个区不可解** | `DL_MAX_ZONES 4`。第 5 个区的锚点**被跟踪**（操作员看得见）但**不参与解算**（`ZONE_FULL` 诊断，1/50 打印）。区数上限需要多大取决于部署，**未做**动态回收（桶一旦建立就不释放） |
| **M4：上位机仍无分区管理界面** | 标签侧已经按区解算并发布 `zone_id`，但上位机一次只能组一个区、不能划区、不能在多个区之间切换查看。**M5 未实现** |
| **M3：上位机仍只有"选 Root"这一个控件** | `AT+NETSTART=<root_rank>` 的语义已从"全网 Root"变成"本区参考锚"，但上位机界面/协议**没有"分区"这个概念**：一次只能组一个区、只能指定一个参考锚。多区组网、`DL_MAX_ZONES 4`、区的划分策略**未实现**（M5） |
