## 一、系统角色与端到端流程

### 1.1 四个节点

| 角色 | 代码位置 | 硬件 | 在系统中的职责 |
|---|---|---|---|
| **Gateway** 网关 | `uwb_gateway/Src/gateway_cmd.c` (3347 行) | STM32L412 + DW3210 | PC 与 UWB 空口之间的桥：接 PC 的 AT 命令、翻译成 UWB 帧发给基站；收标签/基站的 UWB 帧，转成 ASCII 行回给 PC。**不参与定位、不占槽**（`example_selection.h`："pure sniffer, no anchor role"） |
| **Anchor** 基站 | `shared/fusion_anchor/fusion_anchor.c` (3366 行) | STM32L412 + DW3210 | 角色二合一：**Root**（cs_level=0，占槽 0，定义栅格原点、广播时隙表、跑 DS-TWR 修正、填 presence 位图）与 **Child**（按 Root 时隙表排自己的槽）。广播 67 字节 TimeSync 信标 |
| **Tag** 标签 | `shared/fusion_tag/fusion_tag.c` (2108 行) | STM32L412 + DW3210（机器人携带） | 被动收信标、算 TDOA、解算位置、**自己解算后**把结果广播给网关；同时通过本地 UART 输出 ASCII 行给机器人 |
| **Host** 上位机 | `uwb_gateway_py/uwb_host.py` (4819 行) | PC / Python-Tkinter | 组网编排、坐标配置、地图渲染、OTA 进度、离群剔除与轨迹平滑 |

关键设计：**网关不解算位置**，标签解算完再上报结果（`FUNC_DL_POS_REPORT 0xE3`）。网关只做转发与统计。

### 1.2 六段主流程

```
[上电]  Anchor 扫频 → 收邻居信标 → 选举层级(cs_level) →  STATE_SYNC │
[发现]  Anchor 周期广播 0xEC DISCOVERY ──► Gateway 登记设备 ──► Host 设备列表
   │            Gateway 发 0xF3 FIND_ACK，Host 触发 AT+FIND
[配坐标] Host: AT+COORD=uid,x,y,z ──UWB 0xF4──► Anchor 存坐标 + 置 COORD_VALID
   │      (flash 持久化当前是 stub，未生效)
[组网]  Host: AT+NETSTART=root_rank,r1,r2,... ──► Gateway 连续 2s、每 20ms
   │      广播 0xE8 NETWORK_START（携带名册）──► Anchor 回 0xE9 ACK（单播给网关）
   │      Root 按名册建时隙表；Child 发 ALOHA 试探 → Root 在信标时隙表里确认它
   │      ⇒ Child 由 NET_STARTING → NET_WAIT_CONFIRM → NET_RUNNING
[跑栅格] Root 占槽 0，8 槽 × 6.25 ms = 50 ms/轮，20 Hz 信标；Child 按表入槽
   │      Root 每轮批量广播 0xE7 TWR_CORR（各子站路径修正）
[解算]  Tag 每轮解一次（20 Hz）：
   │      收信标 → 维护各锚 tracker → 槽补偿 TDOA 装配 → Gauss-Newton → 质量分
[上报]  Tag 在槽 0 保护窗发 24B 位置帧 0xE3 ──► Gateway ──ASCII "+POS,..."──► Host 渲染
```

旁路流程：**降级/保活**（Root 静默 2 s → 2 Hz 降级帧；全网静默 → 1 s 本地保活帧）、**OTA**（`gw_ota.c` SW-ARQ + `AT+OTA_BCAST`）。

### 1.3 帧与功能码

| 功能码 | 名称 | 方向 | 长度 | 用途 |
|---|---|---|---|---|
| `0xE1` / `0xE2` | COORD_READ / COORD_REPORT | GW↔Anchor | 13 | 坐标回读 |
| `0xE3` | DL_POS_REPORT | Tag→广播 | 24 | 位置上报 |
| `0xE4` | OTA_END | GW→Dev | — | OTA 完成重启 |
| `0xE5` / `0xE6` | OTA_PREPARE / ACK / ABORT | GW↔Dev | — | OTA 换频准备 |
| `0xE7` | TWR_CORR | Root→广播 | 12+4n | DS-TWR 路径修正批量 |
| `0xE8` / `0xE9` | NETWORK_START / ACK | GW→广播 / Anchor→GW | 16 / 15 | 组网 |
| `0xEA` | — | — | — | 未占用 |
| `0xEB` | — | — | — | 未占用 |
| `0xEC` | ANCHOR_DISCOVERY | Anchor→广播 | 24 | 设备发现 |
| `0xED` | CLOCK_FEEDBACK | 观察者→单播 | 27 | 同步误差反馈 |
| `0xEE` | DOWNLINK_BEACON (TimeSync) | Anchor→广播 | 67 | 时钟信标 / 时隙表 / 坐标 |
| `0xF0`..`0xFE` | 网关配置协议 | GW↔Dev | — | PREP/FIND/COORD/OTA/START/STOP/LIST |

分层规则（代码里实际遵守的）：

- **L0 是唯一真相源**。协议头里连"哪一字节是坐标的 x"都写死成 `DL_TS_COORD_IDX`；三个工程（anchor/tag/gateway）共用同一份 `shared/`。
- **L0 不含逻辑**，只有 `#define` 和纯数据结构。
- **L1 只依赖 L0**，不碰硬件，不含状态机 —— `tdoa_solver.c` 的入参是"锚点数组 + TOA 数组"，出参是"xyz + rms + 内点数"，可以脱机跑。
- **L2 持有全部状态**（`g_anchor`、`s_trackers`、`gw_devs`）。
- **L3 不做任何数值计算**，只做展示与编排；数值判定全在 L1/L2。

## 三、算法细节

### 3.1 TDMA 栅格（一切的时间基准）

| 量 | 值 | 出处 |
|---|---|---|
| 一槽 | 6.25 ms | `DL_SLOT_DTU_US 6250` |
| 一轮 | 8 槽 = **50 ms** | `DL_TIMESYNC_PERIOD_MS 50` |
| 一超周期 | 2 轮 = 100 ms | `DL_ROUNDS_PER_CYCLE 2` |
| 信标 / 解算频率 | **20 Hz** | `DL_SOLVE_INTERVAL_MS 50` |
| 槽 0 | 归 Root | `tdma_build_table_from_roster()` |
| 最多锚点数 | 8 | `DL_MAX_TRACKED_ANCHORS 8` / `ANCHOR_MAX_SLOTS 8` |
| 名册上限 / 最小组网规模 | 8 / 3 | `NET_MAX_PARTICIPANTS 8` / `NET_MIN_PARTICIPANTS 3` |

时隙表由 Root 独占构建：**优先用名册**（`tdma_build_table_from_roster`，P2-7 —— 运行期间槽位不再移动），无名册时才退回按邻居 rank 升序排（`tdma_build_table_from_neighbors`）。Root 每收一帧信标就重建表。

子站入槽判据是 `real_slot != 255 && !s_twr_corr_stale`（`fusion_anchor.c:2108`）—— 判据是"DS-TWR 修正是否过期"，不是"是否收到过 corr"，因为 corr 只能**撤销**槽位、不能**授予**槽位。Root 5 s 收不到信标时子站主动清槽退网（`tdma_may_tx`），因为错时隙的信标会污染整轮所有锚点的 TDOA。

### 3.2 DS-TWR 路径修正（Root 侧解算）

子站信标带三个量：`T2`（自身 TX 时刻）、`r1`（收到 Root 参考帧的 RX 时刻）、`refc`（该参考帧的 cycle id）。Root 侧已知 `r2`（自己的 RX 时刻）、`T1`（自己那一轮的真实 TX 时刻，存于 `s_root_tx_ts` 环形表）：

```
(r2 − T1) = prop_R→X + f·(T2 − r1) + prop_X→R
⇒ 2·prop = (r2 − T1) − f·(T2 − r1)
prop_child = prop_root / f_root        (换算到子站时钟单位)
```

要点：

- **T1 必须用 Root 的实测 TX 时刻，不能用标称栅格时刻** —— 否则 Root 自身的栅格误差会整段漏进解出的传播时延里。
- 合理性门限：单程 0.2 m ~ 100 m（`DL_TWR_CORR_MIN_DTU 40` / `DL_TWR_CORR_MAX_DTU 22000` DTU，1 m = 213.20 DTU）。
- IIR 平滑：`(old·3 + new)/4`，路径缓慢变化、测量有多径抖动。
- Root 每轮**一批**广播 `FUNC_TWR_CORR 0xE7`，每条 4 字节（rank u16 + corr_dtu u16），最多 8 条；新鲜度上限 `DL_TWR_CORR_MAX_AGE_CYCLES 2`（子站按同一 cycle 判定过期）。

### 3.3 时钟同步（`shared/shared_data/clock_sync.c`，factor/offset 双状态）

模型：`global = factor × local + offset`，其中 `factor = 1.0 + cfo_raw / 67108864.0`（2^26，`CS_CFO_TO_FACTOR_DIVISOR`）。

- **滤波**：Kalman 形式，过程/测量噪声按 50 ms 节拍标定（`CS_DEFAULT_FACTOR_PROC_VAR 1e-13`、`CS_DEFAULT_FACTOR_MEAS_VAR 4e-12`），offset 走 RC（`CS_DEFAULT_RC_ALPHA 0.30`）。
- **率窗口**：16 样本滚动窗，至少 8 个才出率（`CS_RATE_WINDOW_SAMPLES 16` / `CS_RATE_MIN_SAMPLES 8`）。窗口用首尾两点算率，所以**单个坏帧能毒化整窗** → 前面加一层**样本级门限**（`cs_gate_check`）：候选样本的区间率必须落在窗口内区间率的 **中位数 ± 4·MAD** 内（稳健统计，不依赖滤波器状态，否则会死锁），否则直接丢弃（`CS_GATE_MIN_INTERVALS 3`）。
- **离群门限**：CFO 5 ppm（`CS_FACTOR_OUTLIER_CFO 5e-6`）、时戳 1 ppm（`CS_FACTOR_OUTLIER_TS 1e-6`）。
- **钳位**：预热后 factor 偏离 1 超过 **2 ppm**（`CS_FACTOR_CLAMP 2e-6`）就钳住；预热期（`CS_WARMUP_UPDATES 8` 次更新前）放宽到 50 ppm（`CS_FACTOR_CLAMP_WARMUP 50e-6`）。

### 3.4 槽补偿 TDOA 装配（`tag_solve()`，全项目最核心的一段）

**主公式**：

```
toa_equiv = rx_local − slot × slot_dtu_eff − tx_err
slot_dtu_eff = DTU_PER_SLOT × slot_rate
DTU_PER_SLOT = DL_SLOT_DTU_US × UUS_TO_DWT_TIME = 6250 × 63898
slot_rate    = 标签时钟 / Root 时钟        (P1-4 独立通道估计，见下)
```

三个分支：

| 分支 | 条件 | 做法 |
|---|---|---|
| **Root 参考**（正常） | Root 在候选集里 | 每个锚的 `tdoa_avg`（在 RX 路径里与**同轮** Root 的 TOA 配对后，做 8 轮滑动平均，`TAG_TOA_AVG_N 8` ≈ 0.4 s）→ `toa_dtu[0] = 0`，其余填相对 TDOA。**天然轮次一致，不需要 cycle 过滤** |
| **非 Root 参考** | Root 不在集里 | 用绝对槽补偿 TOA（`rx − slot×slot_eff − tx_err`），再相减。不可平均 |
| **兜底** | 锚点 `slot == 255`（没被 Root 确认 / ALOHA 态） | 直接用原始 RX 时戳相减，**必须同轮**，且主导轮内不足 3 个锚点时放弃本轮（`TDOA_CYCLE_WAIT`） |

**为什么必须减去 `tx_err`**：信标"瞄准"的栅格时刻与真正离开发射的时刻差两截 —— DX_TIME 寄存器只能表达 256 DTU（4 ns）整数倍，标称时刻被**向下取整**，信标最多早发 255 DTU ≈ **1.2 m 路径**；再加上器件 TX 管线时延 δ。所以每帧都要发布"出发误差"，且它必须是**偏差量（时长）而不是时间戳** —— 原始时间戳活在发送方时钟里，其 offset 吸收了 Root→子站的传播时延，跨锚点没法相减。

**为什么 `slot_rate` 要单独估**：时钟滤波器的 factor 会被离群门限拒绝更新，率就冻结了；而冻结的率正好是槽补偿最不能用的东西。所以标签另开一路（P1-4）：直接用相邻两帧 Root 信标的 `Δrx_local / Δtx_remote`，取最近 5 次的中位数，**每帧都更新**（不管滤波门限收没收）。接受区间 0.99~1.01。

**接受窗**：`|TDOA| ≤ 150 m`（`TDOA_MAX_PATH_M`）。

**候选筛选**：锚点必须同时满足 `slot != 255` **且** `coord_valid`。没有坐标的锚点贡献的是"到原点的距离"，会把整个解往 (0,0) 拽。

**循环一致性**：信标带 16 bit cycle id，一轮错位 = 50 ms = 3.19 M DTU，远超接受窗。Root 参考路径因为平均值本身轮次一致，不需要过滤；兜底路径**必须**过滤。

**tracker 过滤**：解算前先剔掉 `desynced` 的锚点和超过 `TAG_TRACKER_FRESH_MS`(250 ms) 没心跳的锚点；参考锚点按 `score = quality×1000 − age_ms` 选最优。

### 3.5 位置解算（`shared/downlink/tdoa_solver.c`）

```
TDOA_cm[k] = (toa[k] − toa[0]) × 0.46907 cm/DTU   (CM_PER_DTU_F)
残差 res[k] = (r_k − r_0) − TDOA_cm[k]
雅可比 J = ∂(r_k − r_0)/∂x = u_k − u_0             (u = 单位方向向量)
正规方程 (JᵀWJ) Δ = −JᵀW res
```

- **Gauss-Newton**，最多 12 次迭代（`MAX_ITER 12`），收敛判据：步长 < 0.10 cm（`CONV_THRESH`）或 RMS 改善 < 0.02 cm（`CONV_DIFF_THRESH`）。
- **自适应阻尼**：残差上升 → 阻尼 0.3（`DAMP_FACTOR`），连续两次发散 → 0.15（`DAMP_DIVERGING`）。
- **离群剔除**（不是直接扔点，是降权）：`|res| > 3.0 × 加权RMS`（`OUTLIER_THRESH`）→ 权重 ×0.5，降到 0.1（`MIN_WEIGHT_KEEP`）以下才彻底剔除。
- **多起点**：上一帧解 + 锚点质心，各跑一次，取残差小的。上一帧解作种子是因为标签两轮之间只移动几厘米，比质心好得多；质心保留是为了防止一次坏解把迭代永久困在局部极小。3D 奇异时自动再跑一遍 2D（标签在锚点多边形内部时雅可比行近乎平行，正规方程病态，旧代码直接返回"无解"）。
- **z 可辨识性**（P2-10，最容易被忽略的一处）：

  ```
  z_info = H[2][2] / (H[0][0] + H[1][1] + H[2][2])
  ```

  这是**几何判据**，不是"锚点高度差"判据。旧判据是"所有锚点高度差 ≤ 1 cm"，但 1 cm 高差在 20 m 展布下 z 方向信息占比近乎为零，高度误差被放大 2000 倍。`z_info < 0.02`（`Z_INFO_MIN`）就判 z 不可辨识 → 该次 3D 结果作废，走 2D 兜底，高度报为"锚点平面高"并置 `Z_VALID = 0`。
- **2D/3D 选择**：`n < 5` 一律 2D（`use_2d`）。4 锚点恰好定解，带噪 TDOA 会被**精确拟合** —— 残差接近 0 而位置可以差 1 米（实测 5 cm TDOA 噪声 → 94 cm 位置误差）。5 个锚点才超定。
- **返回值**：`1` = 解出且高度有效；`0` = 解出但高度无信息（此时 z 只是占位）；`-1` 奇异；`-2` 锚点不足。

### 3.6 质量分（0..1000，越大越好）

```
q_r   = 1000 × clamp(1 − rms_cm/50, 0, 1)      残差项：0 cm→1000, 50 cm→0
q_n   = 1000 × n_inlier / n_meas                 内点率项
q_red = 500 (≤2 测) / 750 (3 测) / 1000 (≥4 测)  冗余项
q     = q_r × q_n × q_red / 1e6
```

`q_red` 的存在理由：3 锚点网络是**恰好定解**，残差天然接近 0，但位置可能差一米 —— 光看残差会给出虚高的分，所以冗余不足要主动打折。

`65535` 是"无解"标记（`DL_POS_QUALITY_NONE` / `TAG_REPORT_QUALITY_NONE`），不是质量值。

**标签的 flags**（24 字节帧的 [20]）：

| 位 | 名称 | 含义 |
|---|---|---|
| 0x01 | `DL_POS_FLAG_Z_VALID` | 高度是**测出来的**，不是锚点平面高 |
| 0x02 | `DL_POS_FLAG_SOLVE_VALID` | 位置是新鲜解 |
| 0x04 | `DL_POS_FLAG_3D_SOLVED` | 解算确实按 3D 跑的 |
| 0x08 | `DL_POS_FLAG_DEGRADED` | 标签活着但**没有网络** |

[21] 是残差毫米数（`DL_POS_RMS_MM_MAX 255` 饱和）。

### 3.7 上行栅格与保护窗（标签怎么发）

正常上报必须落在**槽 0 的保护窗**（Root 信标之后、槽 1 信标之前的空档），否则会压到基站信标上 —— 既破坏那个基站自己的接收，又污染标签自己的 TDOA。

```
目标时刻 = guard_hw + TAG_REPORT_DELAY_US(3000) + ALOHA 抖动(0..1200 µs)
          ⇒ 落在 6.25 ms 槽的 3.0~4.2 ms 处，余量 2.05 ms
```

标签**自己维护一条 50 ms 栅格**（`s_guard_hw` / `s_uplink_ms` / `s_last_tick_ms`），相位锁在 Root 信标上：信标纠正相位与保护窗起点，**丢一个信标就在标签自己的 device-time 域外推 50 ms**（率误差 20 ppm × 50 ms = 1 µs，远小于 6.25 ms 槽）。所以"丢一个信标"不等于"标签哑一整轮"。

延迟发送失败时重试 2 次、每次提前 200 µs（`TAG_TX_RETRIES 2` / `TAG_TX_RETRY_STEP_US 200`），实在不行退即时发送 —— 但只在保护窗还开着时才发，宁可丢帧也不污染测量。

### 3.8 降级与保活（三态可区分）

| 状态 | 判据 | 行为 |
|---|---|---|
| 正常 | Root 在 2 s 内有心跳 | 20 Hz 位置帧 |
| 降级 | Root 静默 > `TAG_ROOT_TIMEOUT_MS 2000`，但**其他**锚点还在 | 收到任何信标后立刻发一帧降级报告，2 Hz（`TAG_DEGRADED_REPORT_MS 500`），帧带 `DEGRADED 0x08`、quality = 65535 |
| 静默 | **全网**静默 | 之前会彻底哑掉 → 已加本地保活：`TAG_ALIVE_KEEPALIVE_MS 1000`，1 s 内没有任何上行发出就补发一帧降级报告 |

"标签还在但没位置"和"标签断电了"必须在地图上可区分 —— 保活就是为这个。当前实现里标签只发**解算结果**，不上报原始时戳，所以没有多标签上行调度（用户已明确：标签的消费者是机器人，UWB 上行只用于调试地图）。

**不变量**：降级上报不能只依赖「收到信标」—— 全网静默时没有任何信标可依赖，必须有本地兜底。

### 3.9 seq 单一来源与丢包统计

- `s_report_seq++` 只在 `tag_report_publish()` 里加一次（每轮一次）。**一帧只构一次**（`s_report_buf`），UWB 帧和本地 ASCII 行**从同一批字节渲染**，两者不可能说不同的话。
- 网关侧算模 256 的 seq 跳变：跳变 > 1 且 ≤ `GW_POS_MAX_GAP`(64) 才算丢包；**排除 DEGRADED 帧及其后一帧**（降级时是故意降速，不是丢包）；输出 `+POSMISS,<uid>,<本次丢>,<累计丢>`。

**已知偏差（未修）**：seq 在**解算栅格**（绝对 50 ms）上递增，而无线电上行跑在**锁 Root 的 50 ms 栅格**上，两者会缓慢相对漂移，于是帧里带的 seq 偶尔跳 2（网关误算 1 丢）或跳 0（网关 `pos_rx` 少计，但 `+POS` 仍会输出）。统一两者需要动延迟发送的时序，无硬件验证前不值得冒险。

### 3.10 组网状态机（网关侧，非阻塞）

```
GW_NETSTATE_IDLE(0) → STARTING(1) → WAIT(2) → RUNNING(3)
```

`AT+NETSTART=<root_rank>,<r1>,<r2>,...`：

- **名册是强制的**（P2-12）。没有名册直接拒绝并回 `+NETSTART_ERR,NOROSTER` —— 旧版会退化成"Root + 网关恰好认识的所有基站"，把操作员没选的基站悄悄拉进网络，而没坐标的基站会把 TDOA 解拽向原点。
- 网关**连续 2 s、每 20 ms 广播一次** `0xE8 NETWORK_START`（`GW_NETSTART_BURST_MS 2000` / `GW_NETSTART_PERIOD_MS 20`），**不阻塞**：广播在主循环里跑，ACK 走普通 RX 路径（所以不会丢帧）。
- 输出三个语义分开的行：

  | 行 | 含义 |
  |---|---|
  | `+NETSTART_OK,<ack_cnt>,<root>,<miss_cnt>,<miss名单…>` | 谁**回过话**（ACK） |
  | `+NETGRID,<on_grid_cnt>,<roster_n>` | 谁**真的在栅格上**（信标里 slot ≠ 255 的成员）。burst 刚结束时通常是 0，**不能**读成"组网成功" |
  | `+NOCOORD,<ranks…>` | 名册里已知没坐标的基站。**是警告不是拒绝**（它们会被标签自己从解算里剔掉） |

- 按钮状态由上位机的 `net_phase()` 驱动，**不由 `+NETSTART_OK` 驱动**：收到 OK 只置"组网中 n/m"，只有轮询到 phase == RUNNING 才显示"✓ 组网成功"。名单不全时**绝不**显示成功。

### 3.11 坐标有效性传播

一个基站**没有坐标**对解算的伤害是隐蔽的：TDOA 是距离差，没坐标的锚点贡献的是"到原点的距离"，把解整体往 (0,0) 拽。所以有效性必须一路带着走：

```
Anchor 收到 0xF4 COORD_WRITE → s_coord_valid = 1
   → 信标 flags 置 DL_TS_FLAG_COORD_VALID(0x08)
   → 标签据此决定该锚点能否进解算（不能的仍留在表里，操作员要看得见是谁）
   → 网关从信标学到状态 → 输出 +COORDSTAT
   → 网关回读 0xE1 → 0xE2，读 ackbuf[16] 的 valid 位
   → 网关 gw_set_coord_state() 记账
```

注意 `s_coord_valid` **不从 flash 保存结果推导**（flash 现在是 stub），所以"存过"和"有效"是两件事。

### 3.12 平台层的一个硬约束：DW3210 尾 2 字节损坏

DW3210 通过 SPI 读回的帧，**最后 2 字节会被损坏**。因此：

- **每一帧都以 `0xCC 0xDD` 吸收垫结尾**。
- 所有 `frame_len` 检查都是**下限**：`DL_TIMESYNC_MIN_LEN 63`（兼容老固件的 63 字节信标）、`DL_TIMESYNC_LEN 67`。
- 位置帧 `[22..23]` 是垫，`flags` 在 [20]、`rms_mm` 在 [21] —— 都在垫**之前**，这样才安全。
- 信标里 `rx_ref_cycle` 必须留在 [61..62]（垫在 [65..66]）—— 早期版本垫放在帧中部、活数据在尾部，Root 的 DS-TWR 永远合不上。

## 四、上位机（`uwb_gateway_py/uwb_host.py`）的业务层要点

- **ID 冲突保护**：设备按 uid 单一键存储，若标签 id 与基站 rank 的 CRC16 撞上（16 标签 × 8 基站 ≈ 2%），`handle_pos` **绝不**把标签位置写进 `type == ANCHOR` 的记录（早期版本会把基站画到标签位置上）。
- **离群门限**：`OUTLIER_MIN_M 0.5` / `OUTLIER_SPEED_MPS 3.0`，质量分档 `Q_GOOD 700` / `Q_OK 400` / `Q_OUTLIER 300`。
- **无解帧（q ≥ 65535）** ⇒ 不做平滑、不延长轨迹，只标记 no-fix。
- **z 无效时**地图显示 `~` 而不是伪精确的平面高。
- **地图语义**：未组网的基站返回 `"idle"` 并单独用灰/虚线样式 —— 早期版本返回空串，和 RUNNING 落进同一个颜色分支，"没组网的基站"和"运行中的基站"在地图上长得一模一样。
- **持久化**：`anchor_cfg.json` 存 coords / labels / counter / tag_labels。
- **UART**：921600-8N1（固件与上位机两侧一致）。16 标签 20 Hz 的 `+POS` 负载约 10.2 kB/s ≈ 链路 11%，不是饱和。

## 五、现状与风险（据实记录）

| 项 | 状态 |
|---|---|
| 编译 / 烧录 / 上机 | **全部未做**。本机无 ARM 工具链，只过了 WSL 桩语法检查（标签 EXIT=0；网关 7 个既有 stub 错 `RTC_TypeDef` + `EXTI`×6 是基线，不是新回归） |
| 基站坐标 flash 持久化 | **stub**（`HAL_FLASH_MODULE_ENABLED` 被注释），且卡在 Keil 32 KB 上限（基线 32060/32768） |
| 16 标签上行调度 | **不做**（用户决定：标签消费者是机器人）。`docs/粮库UWB定位系统技术方案.md` 里"≤16 标签"因此没有上行侧支撑，该口径需改 |
| 标签侧率估计窗口 | 标签用单轮 50 ms 估 Root 率（≈20 ppb），基站用 800 ms 窗（≈1–2 ppb）—— 标签是槽补偿的**弱环**，属精度项，未做 |
| 3D 真正可解的部署 | 共面锚点下 z 本质不可辨识到 20 cm 量级；正解是"标签安装高度已知 → 固定 z 解 x/y"，需要一条网关→标签的配置链路，未做 |
| P2-1（solver 内部改 int64 绝对时戳） | 当前三个分支各自内部自洽，**是脆弱点不是现存 bug**，已记录为延后 |
| P2-2（噪声喂进 GN 权重） | 噪声目前只影响参考锚选择与质量分，未进 `weight[]`；用户已接受延后 |
| P2-3（3 锚病态） | 已用 `q_red = 500` 主动打折 + `n<5 → 2D`，不改代码，已记录 |
| P2-4（解算栅格与上行栅格错拍） | 解算用绝对 50 ms 栅格，阻塞会掉解算但不会错位；不改，已记录 |
| seq 与上行栅格相对漂移 | 已记录（§3.9），修它要动延迟发送时序 |
